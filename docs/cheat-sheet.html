Write a rule

F003.claim-once: one gift a day
When      player opens the panel
Provided  not claimed today
Then      button is active
Otherwise shows next-gift time
  • A stable ID: F003.short-id
  • Always an Otherwise: most bugs live there
  • Examples on both sides of the guard
  • Tuning values in Parameters, never in rule text

Ready gate

  1. Intent, experience, scope in and out
  2. Every rule has an example
  3. No blocking ? still Open
  4. Special terms in the glossary
  5. analyze clean on the final state
  6. The designer marks it Ready

Done = played on the target, reviewed by someone else, deviations written back.

Open questions

  • Mark it inline: ? Nothing with a blocking ? is built
  • One register row each: OQ-F001-002
  • Columns: question, owner, blocking, status
  • Status: Open · Resolved: answer · Deferred
  • Phrase it as a choice, recommended option first
  • Business questions go to the owner

Who decides

Owner
What the game does, scope, word meanings
Designer
Design gaps, playtest conclusions
Producer
Priority, scope, ready and done
Agents
Nothing. They stop and report gaps

Graduate to production when

  • A wrong rule costs money or trust (economy, rewards, ads)
  • Other features keep breaking when it changes
  • It is live, changed by people who did not design it
  • Playtests only change its tuning values

Feel and visuals stay in the prototype tier for good.

Job story

When [situation], I want to [goal], so I can [outcome]. One per ticket. Criteria: happy path, guard, error.
